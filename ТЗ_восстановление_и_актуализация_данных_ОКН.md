# Техническое задание

## Разработка модуля восстановления и актуализации данных об объектах культурного наследия Пскова

## 1. Цель

Расширить приложение data-sufficiency-index. Приложение должно собирать сведения об ОКН из открытых источников, сопоставлять их с ЕГРОКН, выявлять неполные, устаревшие и противоречивые значения, сохранять источник каждого значения и рассчитывать показатели по четырём направлениям: техническому, правовому, градостроительному и инвестиционному.

## 2. Исходное состояние

В репозитории уже есть Streamlit-приложение, загрузка CSV/JSON/Excel, загрузка ЕГРОКН, получение данных OpenStreetMap через Overpass, нормализация, аудит полноты, базовый индекс и сохранение CSV-снимков.

Основные файлы:

~~~text
okn-data-assessment/core.py
okn-data-assessment/app.py
data/raw/
data/processed/
sources.csv
tests/test_core.py
~~~

Существующие функции сохранить и расширить:

~~~python
load_file()
normalize()
fetch_overpass()
fetch_json_source()
fetch_mkrf_dataset()
save_snapshot()
audit()
calculate()
apply_updates()
priority_table()
~~~

## 3. Территория

Основная территория — город Псков. Фильтрация не должна включать все объекты Псковской области.

Использовать признаки:

~~~text
region = Псковская область
city = Псков
~~~

Если отдельных полей нет, применять адресную фильтрацию и направлять неоднозначные записи на ручную проверку.

## 4. Источники

| Источник | Назначение |
|---|---|
| ЕГРОКН | базовые сведения об объекте |
| Министерство культурного наследия Псковской области | статус, охрана, реставрация |
| Портал нормативных актов Псковской области | приказы и постановления |
| Администрация Пскова | ПЗЗ, генеральный план, муниципальные программы |
| НСПД и кадастровые данные | участки и пространственная привязка |
| OpenStreetMap / Overpass | здания, дороги, остановки, инфраструктура |
| ЕИС закупок | проектирование, ремонт и реставрация |
| Инвестиционный портал Пскова | свободные здания, участки, инвестиционные площадки |
| ГИС «Торги» | продажа, аренда и приватизация имущества |

Для каждого источника хранить URL, тип, территорию покрытия, способ получения, дату обращения и ограничения. Поддержать ручное добавление PDF-постановлений, охранных обязательств, актов обследования, предметов охраны, проектной документации и фотографий.

Официальный акт получает высокий уровень доверия, муниципальная программа — средний или высокий, новость — средний. Оценку по фотографии помечать как предварительную. При противоречии значения сохранять и направлять на проверку.

## 10. Сопоставление объектов

Реализовать функцию match_records.

Признаки: object_id, name, historical_name, address, latitude, longitude.

Рекомендуемые баллы:

~~~text
совпадение регистрационного номера: 100
совпадение адреса: 35
совпадение названия: 35
расстояние до 50 метров: 30
расстояние от 50 до 200 метров: 15
~~~

Статусы: matched, probable_match, possible_match, unmatched, requires_review.

Автоматически объединять только записи со статусом matched.

## 11. Актуализация

Создать функцию compare_snapshots(old_df, new_df).

Она должна находить новые и исчезнувшие объекты, изменения по каждому полю, формировать change_log, пересчитывать качество и создавать очередь проверки.

Сроки актуальности:

| Группа | Срок |
|---|---:|
| правовой статус | 365 дней |
| техническое состояние | 730 дней |
| градостроительные сведения | 730 дней |
| инвестиционные сведения | 180 дней |
| координаты | 1095 дней |
| данные OSM | 180 дней |

Сроки хранить в конфигурационном файле.

## 13. Интерфейс

Добавить разделы:

1. Обзор: количество объектов, координаты, средняя полнота, устаревшие записи, конфликты и очередь проверки.
2. Источники: тип, дата обращения, количество записей, ошибки и ограничения.
3. Карточка объекта: четыре блока данных, источник каждого поля, дата проверки, история изменений и индекс.
4. Очередь проверки: конфликты, отсутствие координат, неоднозначные совпадения и устаревшие значения.
5. Управление обновлением: загрузка ЕГРОКН, загрузка OSM, обновление источника, сравнение снимков и сохранение снимка.

## 16. Тестирование

Добавить тесты для нормализации, фильтрации Пскова, сопоставления объектов, расчёта давности, конфликтов, сравнения снимков, расчёта индекса, пустого источника, недоступного API и журнала изменений.

Минимальные требования:

- тесты проходят без ошибок;
- пустой набор обрабатывается;
- дубли не создаются;
- ошибка API не приводит к падению;
- изменение поля фиксируется в change_log.

## 17. Этапы

### Этап 1. Исправление основы

Фильтрация города, разделение дат, источники и даты проверки, дубликаты, YAML-конфигурация.

### Этап 2. Система источников

Реестр источников, журнал обращений, обработка ошибок, локальные снимки.

### Этап 3. Восстановление

Сопоставление ЕГРОКН и OSM, геокодирование, восстановление координат, градостроительное окружение, ручная загрузка документов.

### Этап 4. Актуализация

Сравнение снимков, журнал изменений, давность, конфликты, очередь ручной проверки.

### Этап 5. Итоговая оценка

Четыре специализированных индекса, общий индекс достаточности, оценка потенциала современного использования, экспорт CSV и JSON.

## 18. Критерии готовности

1. Загружается актуальная выгрузка ЕГРОКН.
2. В выборку Пскова не попадают случайные объекты области.
3. Для объекта можно получить данные минимум из двух источников.
4. Каждое восстановленное значение имеет источник и дату.
5. Различаются устаревшие и актуальные сведения.
6. Изменения между снимками фиксируются автоматически.
7. Противоречия направляются на проверку.
8. Рассчитываются четыре отдельных показателя.
9. Формируется очередь объектов с дефицитом данных.
10. Приложение работает при недоступности API.
11. Результаты экспортируются в CSV и JSON.
12. Основные функции покрыты тестами.

## 19. Первая рабочая версия

Включить технический и правовой блоки, сопоставление ЕГРОКН и OSM, градостроительные показатели по координатам, реестр источников, сравнение снимков, очередь ручной проверки и инвестиционный блок как набор признаков и предварительный индекс.

Точный расчёт доходности, рыночной стоимости и окупаемости в первую версию не включать.
